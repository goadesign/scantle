## Goa Design Announces Surla: The MCP-Native Software Factory that Lets You Build, Verify, and Evolve Production Agentic Platforms Directly from ChatGPT, Claude, Codex, and Gemini

*Built on the Goa Design suite (`goa`, `goa-ai`, `pulse`, `clue`, `model`, and `chorus`), Surla compiles service, agent, and MCP contracts deterministically from a single Go design—so coding agents spend tokens only on business logic, and every generated platform ships with Goa-AI’s token-efficient agent contracts and per-change runtime token budgets—running anywhere from a single zero-dependency binary on a laptop to multi-region Kubernetes.*

**SANTA BARBARA, Calif. — October 29, 2026** — Today, the Goa Design team announced **Surla**, an open-source, MCP-native software factory for engineering and product teams shipping AI agents that take real actions—issuing refunds, modifying orders, controlling equipment, or filing tickets—and must keep running reliably for years. Exposed as a Model Context Protocol (`MCP 2026-07-28`) server with asynchronous task tracking (`TaskExchange`) and interactive MCP Apps, Surla lets backend and platform engineers and their product partners use the AI assistant they already work in—**ChatGPT, Claude, Codex, Gemini, or Cursor**—to bootstrap a complete agentic service (or add a single Go agent service calling existing non-Go services), run the generated target locally as a single Go binary with zero external daemons, verify crash and cost safety independently, and deploy unchanged to any cloud or on-premises cluster.

Engineering leaders adopting AI coding agents face a growing maintainability and reliability gap. Empirical research from **GitClear** (*"Coding on Copilot: 2023 Data Suggests Downward Pressure on Code Quality,"* 2024; *"AI Copilot Code Quality: Evaluating 2024's Increased Defect Rate via Code Quality Metrics,"* Feb 2025, analyzing 211 million changed lines of code; and [*"The Maintainability Gap: AI Code Quality in 2026"*](https://www.gitclear.com/the_ai_code_quality_maintainability_gap), analyzing 623 million changes across 2023–2026) observed declining code reuse/refactoring, rising two-week code churn, and a **+81% increase in its 2023–2026 duplication measure**, while **Tornhill & Borg’s *Code Red* study (2022)** across 39 proprietary production codebases demonstrated that low-health code contains **15× more defects** and takes **124% longer** to resolve issues than healthy code. When teams build distributed agentic platforms—which require typed tool schemas, MCP servers, durable execution across crashes and multi-day human approvals, live event streaming, and observability—either humans spend weeks wiring infrastructure glue by hand, or autonomous "dark factories" burn token budgets maintaining repetitive boilerplate and weakening their own tests to pass CI.

Surla addresses these challenges by pairing **Model-Driven Software Product Line code generation**—motivated by **CMU Software Engineering Institute (SEI)** product-line case studies showing reduced ongoing maintenance effort and faster time-to-market—with **process-isolated behavioral verification**. Instead of asking LLMs to write and maintain transport and schema plumbing, Surla expresses services, agent toolsets, MCP endpoints, evaluation suites, and C4 architecture diagrams in a single executable Go design (`design/*.go`), guided by Surla’s built-in **Golden Path Architecture Playbook** (`surla://golden-path`). Every time a capability changes, `goa gen` deterministically compiles the `gen/` transport, schema, and workflow layer at **zero LLM token cost** (in `chorus`, for example, 239 lines of Goa design generate 21,686 lines of `gen/` code alongside 2,566 lines of handwritten Go). Builder agents receive only the compact design slice, the generated `AGENTS_QUICKSTART.md` agent/tool contract guide, and the exact Go interface signatures they need to implement, coordinating in real time over **Chorus** with zero-token background waiting (`chorus watch`) and deterministic **cross-family role routing** (`@architect`, `@builder-<scope>`, `@eval-author`, and `@reviewer`) that pairs builder models with a disjoint model family for evaluation authoring and adversarial review whenever eligible capabilities and scope assignments permit. For production runtime efficiency, Surla scaffolds **Goa-AI’s runtime token and cost controls** by default—including a central stateless gRPC inference gateway (`goa-ai/features/model/gateway` with `middleware.NewAdaptiveRateLimiter` and `pulse` capacity coordination), application-supplied input injection (`Inject` and direct `BindField`), bounded tool views with runtime-held pagination cursors (`BoundedResult`/`ContinueWith`), UI-only data streams (`ServerData`), isolated child-agent workflows (`Use(AgentToolset(...))`), and provider-supported prompt-cache breakpoints (`RunPolicy` `Cache`, which unlock 75%–90% cached-input price discounts on providers that support explicit checkpoints such as Anthropic)—and enforces **per-scenario runtime token and cost budgets** in `surla.verify` on every change.

### Three Moments That Give Engineering and Product Teams Real Confidence

Surla uses **MCP tools, asynchronous `TaskExchange` handles, watchable resources, and interactive MCP Apps** inside ChatGPT, Claude, Codex, or Gemini so product owners and engineers share one source of truth:

- **1. Confirm What It Understood Before Any Code Is Built (`surla.bootstrap` & `surla.propose_change`):** Ask your assistant for a new capability in plain English. Before spending build tokens, Surla restates your request as concrete input-to-outcome examples (mapping each example to a deterministic or model-judged check in an isolated evaluator), surfaces genuine domain ambiguities (such as whether a \$50 refund limit includes tax and shipping), and displays the C4 architecture map (`model`), structural contract diff (`surla diff`), and server-injected identity fields (`Inject`/`BindField`). Starting a build or merging requires an authenticated human operator session—never a model self-approval.
- **2. Try the Real Candidate Before You Merge:** As soon as the candidate build passes repair checks, Surla boots the exact candidate binary in an interactive sandbox (**Tier 0** runs locally as a single Go binary in memory with zero Docker or database setup). Product owners and engineers can replay each confirmed example with one click, preview the target service's own `ToolUI` MCP App views (including an optional, replaceable **OpenUI** viewer starter) alongside raw structured results, or type free-form prompts against stateful dependency simulators clearly labeled *"Simulated payment system: no real money moves."*
- **3. See What Was Checked, By Whom, and What Was *Not* Tested (`surla.verify` & `surla.merge`):** In **Tier 1 (`surla up --durable`)**, Surla runs a supervised local durable stack (`.surla/state/`) and tests the candidate from an access-isolated evaluator that builder agents cannot read or edit. The verification report shows the full check denominator across your confirmed examples, unseen audit scenarios, Temporal workflow history replay, worker `kill -9` crash recovery (proving a killed worker does not double-refund a customer on retry), per-scenario runtime token budgets, and an explicit **"Not Tested"** scope box—deploying unchanged in **Tier 2** as stateless Linux containers to any cloud or on-premises cluster.
